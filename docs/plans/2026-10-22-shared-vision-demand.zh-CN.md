# 共用分块需求与全局并行额度

2026-10-22。承接用户对仅气泡、仅游离文字、工作流资源和自定义全局上限的确认。

## 行为契约

| 分块范围 | SEG 节点的资源 | 后续 OCR 节点的增量资源 |
|---|---|---|
| 仅气泡 | 气泡 SEG | DET、按节点语言绑定选择的 REC；在输入气泡内检测文字 |
| 仅游离文字 | DET | 按节点语言绑定选择的 REC |
| 气泡和游离文字 | 气泡 SEG、DET | 按节点语言绑定选择的 REC |

没有 OCR 节点就不预热文字识别模型。机翻路线仍由工作流机翻节点决定；直接发 API 不因分块而加载本地机翻。纯字幕工作流不申请视觉模型。

漫画章节、阅读器单页、屏幕翻译、视频调用共同的 `WorkflowProgram.visionModelDemand`。结果交给原有共享视觉池，按所有者需求并集保留模型，差异卸载空闲资源，新增资源按需预热。一个所有者关闭不会卸载另一个所有者仍需要的模型。章节队列先保留待运行需求并集，预热当前任务子集不再覆盖此并集。

仅气泡的 SEG 阶段停止调用 DET。真正执行 OCR 节点时再检测泡内文字，避免把 SEG 阶段的空文字行误认成“没有文字”。直接发送气泡图片到 API 的成果保留气泡几何。仅气泡预处理缓存改用新版本键，避免复用旧阶段行为。

## 全局上限

- SEG 和 OCR 各用一组进程内共享池；DET 与 REC 共用 OCR 额度。自定义 1–8 是该资源全局上限，不再被固定两实例或外层总计算两许可截断。额外模型实例按需创建，不在设置为 8 时立即预热八份。
- 自动模式继续依据 CPU、可用内存、应用堆预算计算；SEG 自动最多 2、OCR 自动最多 4，沿用自动策略。自定义数值是上限，不保证所有阶段一定达到该并行度。
- 屏幕设置与“API 与翻译引擎”共享并行数；屏幕各自的加速后端设置保留。旧数据没有全局数量键时继承屏幕旧数量，之后统一读写全局值。
- 上调额度后，已经排队的调用也可获得新增额度；下调后等待当前调用自然返回，后续准入使用新上限。忙碌实例不强制卸载，空闲多余视觉实例被清理。
- 机翻继续使用既有共享池、路线与内存预算计算；移除外层固定两许可限制，等待中的请求重新读取当前路线额度。未新增一套视频专用加载/并行算法。
