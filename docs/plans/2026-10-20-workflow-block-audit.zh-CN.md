## 3. 优先收口的问题

### 新增上下文的输出不可选

用户反馈“新增上下文的输出无法选中上下文类型”。本轮后续追查确认：

- [输出类型过滤](../../app/src/main/java/com/lmreader/ui/workflow/WorkflowNodeEditor.kt#L118)明确允许 CONTEXT；[变量类型编辑](../../app/src/main/java/com/lmreader/ui/workflow/WorkflowNodeEditor.kt#L344)也提供上下文类型。输出处选的是已存在的变量引用，不会在此创建变量。
- [可写目标过滤](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowEditing.kt#L93)排除只读父层和循环条目；[异步作用域规则](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowValidation.kt#L100)会把外层变量标成只读。“新增上下文”没有文本/列表追加那样的特殊写入通道。
- [静态校验](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowValidation.kt#L238)与[实际执行](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowRuntime.kt#L509)都按普通写入处理；只修改界面过滤仍不能执行。并行写同一上下文还需定义消息顺序与合并规则。
- [选择器](../../app/src/main/java/com/lmreader/ui/workflow/WorkflowNodeEditor.kt#L208)目前只提示“无匹配变量”或“此处变量不可用”，没有区分尚未创建、声明在后、外层只读、条目只读或搜索不匹配。

以上确认了能导致空候选的代码路径；尚未取得用户这份工作流，不能据此认定具体触发条件。已有[上下文运行测试](../../core/workflow/src/test/kotlin/com/lmreader/core/workflow/WorkflowTest.kt#L108)显式把内部循环设为同步，也未覆盖本次编辑操作。

首轮应提供“在此创建上下文”的入口，或清楚指引先在当前可写作用域创建上下文；对不可选变量显示原因。需要跨项积累的上下文先使用明确定义的同步或有序收集流程，不自动关闭所有异步循环。若要允许共享异步追加，另行设计并一起修改编辑器、校验、执行器和迁移规则。

验收至少覆盖：同层先声明后写入、外层同步可写、外层异步只读、循环条目、未声明及声明在后、保存重开；确认提示可操作且运行规则相符。本项为用户新增反馈后的 Codex 追查，尚未再送 DS 复审，也未运行 UI 复现。

### 合并列表的规则不一致

[编辑器](../../app/src/main/java/com/lmreader/ui/workflow/WorkflowNodeEditor.kt#L120)只允许列表输出；[新建默认值](../../app/src/main/java/com/lmreader/ui/workflow/WorkflowEditorScreen.kt#L357)落到文本目标与文本输入；[校验](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowValidation.kt#L226)和[执行](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowRuntime.kt#L138)接受文本拼接。

建议新建默认选择兼容列表，无可用列表时提示先创建变量。明确合并列表只合并同类型列表；旧程序若曾将它用于文本，走显式迁移或兼容提示，不能悄悄改变旧任务语义。运行验证须包括新建、编辑、导入、嵌套及异步父层目标。

### 纯文字流程被漫画校验强制要求 SEG

[当前校验末尾](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowValidation.kt#L250)要求漫画、章节、页面结构各一个，并要求存在 SEG。已有类型化文本和列表处理仍可复用，但纯字幕/音频/阅读辅助不能直接作为独立流程通过这套规则。

建议增加工作流输入场景：图文、视频帧、音频字幕、阅读辅助等。按场景提供入口、系统变量和必要结构，旧漫画流程保留原规则；不要通过塞假图片/空 SEG 来绕过校验。工作流分类与执行场景不是同一个字段。

### 回写、身份变化和错误提示不够直观

- `EACH` 可能回写所遍历的原列表；收集结果与回写原列表是两件事，界面都要说明。字幕先后顺序使用有序结果收集，避免依赖并行追加顺序。
- SEG 重建后旧区域虽然类型仍相同，ID/图片引用可能已失效。提前提示依赖受影响；以宿主验证作为最后保护。
- 按顺序回填运行时检查正整数和边界；对能静态判断的非法常量，在保存时提前提示。
- 变量候选说明“为什么不能选”，显示有效类型/来源/可写范围；空候选给出下一步，而不是只留空白。

## 4. DS 意见中经核对修正的部分

**“整漫画单请求开关无人处理”不能成立。** 标准 AndroidWorkflowHost 不直接消费该标志，但[翻译队列的宿主覆盖](../../app/src/main/java/com/lmreader/ui/queue/TranslationQueueCoordinator.kt#L460)在 api/apiStream 中读取 call.wholeManga 并管理整作品请求。后续应验证不同宿主的支持和说明，不应直接删除开关或宣称全部失效。

**“没有引擎控件，所以机翻要求未满足”不能成立。** [translationEngine()](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowTranslationRoutes.kt#L6)和[执行宿主](../../app/src/main/java/com/lmreader/ui/workflow/AndroidWorkflowHost.kt#L236)在缺省时都选择 Bergamot；错误只针对不支持/非法绑定。可补只读引擎说明，无需为了选择器新增功能而制造配置步骤。

**字幕不必扩成 RegionKind 的一种气泡。** 当前[RegionKind](../../core/model/src/main/kotlin/com/lmreader/core/model/LocalVision.kt#L13)是 BUBBLE/FREE_TEXT，适用于画面区域。音频/导入字幕独立保存为带起止时间的条目；区域语义和遮罩绘制策略分开扩展，旧文件解析需要兼容。

**SEG 清空旧记录有函数实现依据。** DS 第二轮只读到调用点，对这一说法提出保留意见。Codex 核对 [replaceSegBubbles()](../../core/workflow/src/main/kotlin/com/lmreader/core/workflow/WorkflowRuntime.kt#L124)：它在写入新 bubbles 后把 records 设为空列表；这一副作用保留在检查表中。

## 5. 视频两条工作流的复用范围

### 视频画面

本地媒体取帧 → 带播放时间的帧引用 → 适配现有图像工作流 → 区域/译文结果 → 播放遮罩与持久化时间区间。

复用 SEG/OCR/机翻/API、现有区域轮廓、部分视频区域匹配和绘制逻辑。新增帧来源、播放时间锚点、解码背压、结果时间有效性和播放覆盖层；不复制另一套识别翻译执行器。

帧坐标须处理旋转、显示缩放及黑边；跳转后迟到结果不能覆盖当前画面。识别按需取帧和去重，不把每帧原图长期保存。当前页成果限制约四百万分析像素，4K 视频不可直接套用整帧持久化，应验证分析尺寸和坐标映射，保留原视频分辨率。

### 视频音频字幕

本地音轨/已有字幕 → 专用离线 ASR、语音 LLM API 或字幕解析 → 有序时间片段 → 文本翻译 → 独立字幕轨。

用户已确定优先离线 ASR，语音 LLM API 为可选路线，已有字幕可导入。候选专用组件可比较 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) 与 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)，不在计划阶段宣称哪一个更快或适合所有设备；最终选择取决于实际模型、语言、时间戳和设备测量。

须补音轨读取、音频解码/分段、音频引用和识别输出契约。保留时间、顺序与说话间隔；分段翻译考虑相邻上下文，禁止把段落文本译完后丢失时间关系。无声、音乐、重叠语音、取消、失败重试及模型释放单独验收。

专用 ASR 不等于通用聊天大模型。当前 API 附件模型只有图片，语音 API 需要增加真实音频能力；不能仅因某提供方名称相同就标记已支持。此路线不需要重编码或导出视频。

## 6. 扩展与易用性整改的共同规则

一份块定义至少包含：稳定类型 ID、版本、名称/分类、输入、输出、默认值、空值和引用规则、可用场景、子步骤、作用域和副作用。编辑器和校验共享声明；执行处理器以同一声明验输入输出，复杂块保留专用交互。

新增扩展仍需要处理器/组合流程、迁移和验证，不把“加一行定义”宣传为任意能力都能自动实现。保留旧 WorkflowKind/序列化的兼容映射，未知块不能静默忽略。

- 引擎适配块：接入新识别、翻译、ASR 等引擎，声明模型、初始化、并发和释放；本地服务与原生平台适配明确区分。
- API 规则块：允许新增请求结构、认证/附件映射和结果解析规则，不限定为现有聊天协议。
- 组合块：封装现有步骤，明确暴露输入输出及内部变量范围。这与新增引擎/API 规则均属于正式扩展用途。
- Agent：通过相同块/工作流调用能力，另管会话与上下文；无 API 时也允许在 Agent 入口执行已有本地翻译流程。
- 遮罩：独立声明绘制策略和坐标约定；画面区域与字幕轨分别处理。
