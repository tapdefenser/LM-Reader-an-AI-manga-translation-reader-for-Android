# 图库、视频播放器与统一任务改造方案

**proposal-1 · 2026-10-20 · 供用户审阅、后续分批执行。**

依据：用户在手机试用后的本轮要求、[原最终计划](2026-10-20-final-plan.zh-CN.md)、[猫爪检查附录](2026-10-20-workflow-block-audit.zh-CN.md)、[执行进度](2026-10-20-execution-progress.zh-CN.md)，以及 Codex 与本地 DS 的只读代码调查和 Android 官方文档。本轮只形成方案，不实施功能、不构建、不操作设备。静态发现与待设备复现的问题分别记录。

## 1. 本次纠正的方向

上一版交付了取帧、工作流和成果保存的技术链路，但入口、播放器、后台队列和编辑方式没有组成日常可用的产品。先前测试通过记录保留，不能当成本次要求已经完成。

新的完整使用路径是：**进入图库自动看到视频 → 点击即可播放 → 设置翻译后自动加入视频书架和统一任务队列 → 在后台按媒体时间处理 → 播放时读取已完成成果 → 分别校对画面气泡和字幕。** 播放器无需保持打开才能翻译。

本方案替代原计划中“独立本地视频入口、主动导入为主、播放器页面直接执行连续翻译”的交互和调度安排。原计划的成果保护、输入场景、ASR 评估、原视频不改写、正式成果与缓存分离、备份兼容继续有效。保留名称、包名、签名和现有工作区改动，不顺带展开完整插件平台、Agent 或 iOS。

### 2.1 联合 DS 复核后的可靠性清单

DS 本轮完成只读调查，原始本机记录在 `.scratch/video/ds-redesign-queue-audit.md`。Codex 另行检查单页入口、视频 ON_STOP、优先级调用点、状态恢复、session 池和 API limiter，没有采用 DS 把视频 ON_STOP 停止作为默认后台翻译策略保留的建议，因为这与用户新要求冲突。

- **代码可确认的缺口**：单页无独立持久任务；画面/字幕任务随播放器停止；优先级上下文未从入口传递；视觉实例和缓存预算分散，NMT/API 虽共用底层机制却没有跨类型资源归属。通知只覆盖翻译/导出，不能作为全任务账本。
- **代码可确认的恢复行为**：启动时 RUNNING 转 INTERRUPTED，普通 `resume/resumePaused` 不会将 INTERRUPTED 变成可运行项，“全部开始”才覆盖该状态。新方案需要明确系统中断和用户暂停的分别恢复规则，而不能简单把所有非终态自动重试。
- **需要故障注入/设备复现**：API profile 不同并发配置的竞争、视频 stop 与原子发布、单页发布后取消但计数尚未更新、屏幕会话早于队列初始化、低内存多引擎竞争。它们列入验收，不能把静态怀疑写成已复现崩溃。
- 视频 `publishFrame` 已在写成果和更新索引前检查执行代次，成果 store 也有取消检查；仍需验证检查点与提交锁的边界，不能误写成“完全没有取消保护”。严格 ORDER 模式让后续作品等待是现有显式策略，是否允许同级公平轮转要按用户模式区分，不能一概判为错误。

## 3. 图库与书架：同一个图片/视频选择

### 3.1 位置和记忆规则

- 图库、书架都在内容区下方放一个独立圆角分段控件：`图片 | 视频`，左图标/图片，右图标/视频；明确显示选中态。删除主菜单的独立“本地视频”和主要“导入视频”入口。
- 控件悬浮在内容区下缘之上，有明显间距，不贴系统导航栏，也不与现有任务进度条、悬浮球重叠。建议高度 48 dp、宽度约 216–264 dp、可用内容下缘上方 16–24 dp；这些是首轮布局值，按实机可用空间调整。
- 将现有 `HomeTaskChrome`、任务进度条和分段控件放在一个布局计算体系中，禁止三个页面各写固定屏幕 Y 坐标。列表留足底部 padding，使最后一项可完整滚出。
- 横屏按窗口可用区、安全边距和任务条高度重算位置，宽屏控制最大宽度。小窗口高度不足时缩小外边距，不压缩到难以点击；多选/输入时安排在操作条之外。
- 全局只存一份 `homeMediaMode=IMAGE/VIDEO`，图库与书架立即共用；退出、进程重建和下次启动继续保持。新安装默认图片，恢复偏好时也恢复该值。
- 启动时先取得持久选择再呈现内容，不先闪出图片又跳回视频；模式和对应列表状态按同一导航状态恢复。
- 图片/视频以及图库/书架各自保存搜索、筛选、排序和滚动位置，不因共享媒体模式而共享所有页面状态。视频全部用列表；图片现有网格/紧凑设置保留，不在本轮重做。

### 3.2 图库和书架分别表示什么

图库视频是系统媒体库中可访问的视频全集；书架视频是用户主动收藏或开始翻译的视频引用子集。两者指向同一个 videoId、观看进度、任务和成果，不复制原视频，不重复创建项目。单纯播放不自动加入书架；开始视频翻译自动加入“未分类”，已有分类不改变。

书架视频沿用分类的产品概念，但使用视频成员关系，不把视频伪造成漫画/章节。图库视频筛选以文件夹为主；书架同时支持分类和文件夹。已在书架的菜单显示“已加入书架/管理分类”，不重复添加。

## 4. 系统视频库：首扫、增量、刷新和身份

### 4.1 可发现范围

通过 `ContentResolver + MediaStore.Video` 查询已挂载存储卷，取得 content URI、名称、大小、时长、宽高、旋转、添加时间、母目录和版本信息。首次进入视频区域申请适用的视频读取权限。Android 14+ 可能只授权部分媒体，界面区分“全部可访问/仅部分/未授权”，不能把部分授权结果称为全设备全集。该边界来自 [Android 部分照片和视频访问说明](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。

这里的“全设备”指**系统媒体库已索引且用户允许访问的视频**。应用私有目录、未被媒体库索引或被系统隐藏的文件不保证出现；不为视频发现追加全盘递归扫描。旧 SAF 视频和必要的失效文件重定位保留兼容入口，不能要求所有用户重新导入。

### 4.2 刷新语义

| 时机 | 做什么 | 不发生的副作用 |
|---|---|---|
| 首次有权限进入 | 分页查询全量媒体元数据，逐步显示，建立每卷水位 | 不解码所有封面、不哈希所有文件、不自动翻译 |
| 每次应用从后台/启动进入前台 | 合并一次增量发现，加入新视频；会话内事件做防抖和去重 | 不重建书架、观看进度和成果，不因普通返回页面重复全扫 |
| 用户点刷新 | 全量核对媒体元数据、目录、大小/时长变化和失效条目 | 不删原视频，不删书架或人工成果，不改变任务顺序 |
| 权限范围改变/存储卷插拔/媒体库版本重置 | 立即校验可访问性，重建受影响卷的水位；必要时提示重新授权 | 不把权限丢失或 SD 卡拔出当成用户删除原文件 |

Android 11+ 优先使用每卷 generation 与媒体库版本做增量水位，而不是只用添加日期；查询开始时固定上界，成功提交该批后再推进水位，失败不跳过记录。旧系统用 ID/时间和去重补查回退。generation 不能检测删除清单，删除与全库校正留给手动刷新；播放/任务打开文件失败时即时标明。版本重置需要重新同步水位，具体依据见 [MediaStore API](https://developer.android.com/reference/android/provider/MediaStore#getGeneration(android.content.Context,java.lang.String))。

普通重进只补新增与必要的访问校验；权限变化时仍必须重新查询当前可见范围，防止陈旧缓存继续展示已经撤回的媒体。该必要校验不等于执行用户意义上的整库清理。

### 4.3 母文件夹、排序和封面

- 文件夹键采用“存储卷 + 完整母目录”，显示末级目录名；同名目录附短路径区分。选某目录只匹配直接位于该目录的视频，不递归包含子目录，不按所有祖先路径重复计数。
- 全量元数据查询使用分页和稳定次序，首屏先显示。封面仅对可见和少量预取项取图，缓存有上限，取图也受统一资源准入控制；缺失宽高/时长按需补查。
- 用户排序如下；升/降序可切换，同值用稳定 videoId 兜底，避免翻页重复或抖动。

| 排序 | 明确口径 | 默认方向 |
|---|---|---|
| 添加时间 | 系统媒体库 `DATE_ADDED`，不是拍摄时间，也不是加入书架时间 | 新 → 旧 |
| 文件大小 | 原视频字节数；未知值排在已知值后 | 大 → 小 |
| 时长 | 媒体时长，不是已经观看时长 | 长 → 短 |
| 名称 | 普通文本名称排序，数字不单独作数值比较 | 升序 |
| 自然数 | 复用 `NaturalOrder`，例如 `2 < 10`；前导零等价时用名称/ID稳定兜底 | 升序 |
| 最多播放 | 本应用播放次数，不冒充读取其他播放器统计 | 多 → 少 |

建议播放次数按一次主动进入产生的观看会话计数：实际累计播放达到 `min(30秒, 视频时长的50%)` 后记 1 次；暂停、跳转、旋转、锁屏恢复和自动循环不重复计数。此阈值是建议默认，不是平台限制；历史数据缺该字段从 0 起，不伪造旧次数。

## 5. 视频列表、状态和三个点菜单

统一列表项：左侧 16:9 圆角封面，封面右下角半透明底显示时长；中部第一行文件名（最多两行、溢出省略），第二行小字 `清晰度 | 文件大小 | 翻译状态`；右侧独立三个点按钮。例如 `1920×1080 · 1080p | 842 MB | 画面 36% · 字幕已完成`。尺寸未知用“未知清晰度”，不猜测。

任务状态与成果状态分开：排队、处理中、正在暂停、已暂停、等待模型/授权/资源、失败；成果可显示未翻译、部分、完成、含人工修改。当前配置变更后保留并标明“旧配置成果”，不能直接算新任务完成。百分比由可计算的采样/字幕单元得出；总量未知时只显示数量/阶段。

| 菜单项（按用户顺序） | 行为 |
|---|---|
| 分享 | 系统分享原视频 URI，授予临时读取；分享译文包或字幕从导出结果进入，名称清楚区分 |
| 添加到书架 | 引用现有条目；已加入时管理分类，不复制视频 |
| ▷ 翻译 / 暂停翻译 | 缺有效配置先开选项；已有配置提交/继续同一目标任务；运行中暂停，暂停后可继续，不造重复任务 |
| 翻译选项 | 打开该视频的选项；主要操作为“加入队列/更新并重新排队”，提交前说明已有人工成果的处理范围 |
| 编辑译文 | 进入画面气泡编辑器，定位当前/最近成果时间；无成果时允许创建人工气泡，不能悄悄开始付费识别 |
| 清除译文 | 选择画面、字幕译文或两者及时间范围；默认保留原视频和原字幕；显式确认涉及人工成果，先停止对应写入者并更新成果代次 |
| 导出 | 选择译文/双语 SRT、可恢复的画面+字幕成果包；显示导出队列和状态，不阻塞列表 |
| 信息 | 文件名、母目录、存储卷、URI、格式/编码、宽高/旋转、大小/时长、播放统计、权限/文件状态、成果及可归属缓存占用 |

“移出书架”在书架的分类管理/多选操作提供，只移除收藏关系；“删除原文件”不混在清译文或移出书架里。原视频未翻译、任务失败等情况都要有可操作状态，不显示一个点了没有反应的菜单项。

## 6. 播放器：观看为主的独立界面

### 6.1 布局与播放底座

点击任意视频列表项直接全屏进入播放器，不先进入项目管理页。上栏半透明渐变：左返回、中间视频名、右三个点；下栏上部是时间与播放条，下部左横竖切换、中间上一视频/播放暂停/下一视频、右视频列表。两侧中部各有透明圆底：左锁定/解锁，右翻译。单击显示/隐藏控制栏，播放中约 3 秒无操作隐藏；暂停、菜单或编辑时不自动隐藏必要控制。

建议用 **AndroidX Media3 ExoPlayer + MediaSession** 替换当前简易 `MediaPlayer` 控制适配，使用自定义 Compose 控制层；不复制其他播放器素材。Media3 提供播放列表、速度、重复/随机及音轨选择基础，可分别参照 [播放控制](https://developer.android.com/media/media3/exoplayer/hello-world)、[播放列表](https://developer.android.com/media/media3/exoplayer/playlists)和[音轨选择](https://developer.android.com/media/media3/exoplayer/track-selection)。实现时统一锁定各 Media3 模块版本，只引入本地播放需要的模块。

- 播放只依赖媒体和已保存成果，不依赖翻译引擎已加载。一个播放会话控制一个当前视频，切换 URI、时间和画面代次一起更新，旧遮罩立即清掉。
- 原画面、画面译文和字幕分层；分析只拿原视频像素。按真实 video presentation size、旋转、像素比例、黑边进行一致坐标映射。
- 播放列表与翻译任务队列分开。由点击来源当时的筛选/排序生成播放列表快照；书架来源就是该分类的列表。增量发现新视频不突然改掉正在播放的前后项。
- 返回图库/书架保存位置，恢复列表原位置；普通退出播放器默认暂停。只有用户选择悬浮窗或明确开启后台播放才继续播放；翻译任务不受播放器退出影响。

### 6.2 手势冲突规则

“双击暂停”和“左右双击快退/快进”不能在同一位置同时触发，建议分区：左 30%、中 40%、右 30%。这里是需要产品验证的默认划分。

| 手势 | 行为与冲突处理 |
|---|---|
| 中间双击 | 播放/暂停；暂停后可同样恢复 |
| 左/右区域双击 | 后退/前进 10 秒，边界夹紧；显示短暂 ±10 秒提示，不同时暂停 |
| 长按画面 | 临时设为 2 倍速，松手/取消恢复长按前速度；若暂停中不偷偷开始播放 |
| 水平滑动 | 按视频总时长百分比预览 seek；默认整幅有效宽度约对应 20% 总时长，显示目标时间和比例，松手只提交一次；长视频可在播放条上精调 |
| 左半边垂直滑动 | 调本播放窗口亮度，离开后恢复系统/原窗口设置，不写系统亮度权限 |
| 右半边垂直滑动 | 调媒体音量，显示比例，正常处理静音/耳机；不连续触发 seek |
| 锁定 | 隐藏普通控制并禁用全部内容手势，只保留明显可用的解锁按钮；系统返回可给解锁提示，不能把用户困住 |

统一手势识别器在触摸阈值后锁定轴；按钮、进度条、系统返回边缘及编辑器拖动有更高命中优先级。进入菜单、编辑或 PiP 时结束长按临时速度；旋转前的播放速度和位置保持。除横竖切换按钮外，系统旋转、多窗口也要正确处理。

### 6.3 右上角菜单与翻译菜单

右上角按顺序：分享、悬浮窗、速度、音轨、播放模式。播放模式为单个循环、列表循环（默认）、播放后暂停、随机；速度提供常用档和记忆，音轨列出真实可用轨及语言，没有多轨时解释当前轨。列表首尾及坏文件的处理明确，随机不在本轮列表未走完时反复抽同一项。

悬浮窗建议首先用系统 PiP，保留视频、遮罩和字幕，隐藏编辑器，使用系统播放控制；返回时恢复同一会话。官方明确建议使用 [PiP](https://developer.android.com/develop/ui/views/picture-in-picture)，而不是用系统悬浮窗权限模拟 PiP。本方案不复用屏幕翻译的悬浮球创建第二个播放器。

右侧翻译按钮菜单：翻译本画面、▷ 翻译/暂停翻译、翻译选项、编辑译文、清除译文。菜单直接显示任务当前阶段；“翻译本画面”捕获点击瞬间的 videoId、源版本、实际 PTS 和配置，提交最高交互优先级任务，不能在排到它时改采另一画面。

建议右上角额外增加“字幕”入口，放字幕开关、轨选择、样式和“字幕工具栏”；这样不会把字幕编辑硬塞进“编辑译文”。这是对用户菜单的明确补充建议。

## 7. 画面编辑与字幕工具分开

### 7.1 画面气泡编辑器

将现有“播放器+设置+字幕表格”的管理界面拆分；保留其可用的预览/配置逻辑，将画面工作区专门设计为“编辑译文”。提炼阅读器共用的气泡草稿、选中/新建/删除、移动缩放旋转、译文输入、字号、撤销、保存/离开提示；UI 外壳不直接依赖 `ReaderTranslationUiState`，由阅读器和视频各自适配。

选择某个气泡后，在播放条下方显示**该气泡**覆盖的时间带，以及左“开始”、右“结束”的输入框和时长；时间格式 `HH:MM:SS.mmm`，验证 `0 ≤ start < end ≤ duration`，支持从当前播放点设边界。编辑时暂停且固定视频与基准帧；预览可跳转检查，不能让持续播放导致拖动对象变成另一个气泡。

新增 `RegionTrack/RegionInterval`：稳定区域 ID、文本/译文、几何关键点或帧引用、起止时间、来源、人工标记和 revision。当前只有帧级 `atMs/untilMs`，无法表达同一帧里两个气泡各自消失，因此必须补区域级时间信息。可跨采样帧做保守关联，但不因相同文字就跨镜头串成同一气泡。人工时间覆盖与几何变更分别保存；原时间观察和人工修订可追溯。

人工删除也保存保护标记，后台恢复不把删掉的气泡自动补回来。修改时间、文本和几何作为一次可撤销草稿保存；基于预览成果 revision 提交，后台迟到结果不能覆盖。编辑器不提供字幕文本/时间修改。

### 7.2 播放器的字幕工具栏

从“字幕”进入工具栏后，播放条下方显示当前活动字幕的覆盖段；工具栏显示原文/译文输入、开始和结束。段左/右有上一条/下一条按钮，跳到目标条目 `(start+end)/2`；依时间排序，不使用重复的 SRT 序号作身份。

- 当前没有字幕时显示可添加状态；新增默认从当前时刻开始、到下一条之前或建议 2 秒结束，边界无空间时让用户调整，不静默覆盖邻条。允许删除、撤销和恢复。
- 多条字幕重叠时保留轨和稳定顺序，显示当前选中条目，不把其余条目丢掉。整体偏移是播放/导出变换，单条起止编辑是正式修订，不相互重复叠加。
- 字幕文字、时间、手工新增/删除都进入正式成果及版本保护；机器重试只补仍允许生成的部分。原字幕和译文分字段，清译文不会顺手删原字幕。
- 样式含字号、字体/可用字形回退、行距、位置、对齐、文字色、描边和背景透明度，支持原文/译文/双语及按视频覆盖全局样式。
- “智能颜色”是可勾选的颜色模式：采样**原画面字幕实际覆盖区**，浅背景优先黑字、深背景优先白字，混合背景保留反色描边/适度底色；做时间平滑和切换滞后，不能每帧闪烁。开关只是显示设置，不触发重新翻译。HDR、旋转、黑边和 PiP 需各自验证；没有可用采样时用稳定描边回退，不显示错误颜色判断。

## 8. 翻译选项、自动入书架与任务结构

主要选项先显示：源/目标语言、**仅画面 / 仅字幕 / 画面与字幕**、对应工作流、准备状态和“加入队列”。画面区显示采样帧率，字幕区显示文字来源；高级项分组折叠，沿用原计划 1.5/2.1，不再堆在播放器上。

| 配置组 | 内容 |
|---|---|
| 画面 | 采样帧率与等价间隔、图像流程、分析分辨率上限、识别范围、匹配阈值、重用/重译范围 |
| 字幕 | 外部/内嵌文本轨或语音识别来源、文本流程、语言、邻近上下文、识别模型/实际音频 API |
| 任务 | 全视频或时间范围、缺能力补齐后继续、现有结果匹配情况；高级资源上限是对全局预算的请求上限，不能突破全局硬上限 |
| 显示 | 遮罩和字幕各自开关与样式；单独保存，不混入需要重跑的语义摘要 |

建议采样档位 0.5/1/2/5 帧每秒，默认 1 帧每秒，并显示“每 1 秒分析 1 帧”。这些是待 ARM 实测修订的产品默认，不是实时性能承诺。小时视频 1 fps 约 3,600 个采样位置；提交前展示预计采样数量，暂不把它转换成未经测量的耗时或费用。

提交时在事务中完成：配置快照/语义摘要 → 保证视频书架成员关系 → 创建或复用唯一活动任务，整片翻译和“翻译本画面”使用同一规则。缺模型、授权或字幕来源时保留任务并显示 `WAITING_CAPABILITY/ACCESS` 的具体节点与补齐入口，不用已经失败的伪完成状态。退出设置未确认不产生任务；重复点击返回已有活动 taskId。纯本地工作流无需 API。

字幕配置固定本次要识别的音轨和字幕源身份；播放器切换听觉音轨不静默改掉已排队的 ASR 任务，修改识别音轨需要在翻译选项中明确更新任务。

一个视频任务可有画面和字幕两个工作分支；各有进度、检查点、失败/暂停和重试状态。允许资源充足时并行，不承诺固定同时跑；一支失败不撤销另一支的完整成果。父任务仅在选中的全部分支完成后完成，部分失败明确列出，不能混成“已翻译”。

## 9. 真正的后台视频画面流水线

### 9.1 两个在途画面与固定媒体时间

把用户所说“两页章节”落为**最多两个在途画面的滑动窗口**，而不是把全片伪装成一个只有两页的持久章节。复用 `ScreenChapterWindow` 的准入/背压思想，在独立的视频宿主里推进时间序列，不修改旧漫画任务定义来迁就视频。

```text
媒体时间采样计划 → 离屏解码 N+1 → [窗口最多两份画面] → SEG/OCR/翻译 N
                                                        ↓
                                       按视频+实际PTS+区域写正式成果
播放器 ──────────────────────────── 只按播放时间读取/验证成果
字幕提取/ASR → 有时间的文字 → 文本翻译 ──────────────────────┘
```

目标时间为 `t(k)=k/fps`，使用整数/有理数计算避免累计漂移，实际解码 PTS 一并记录。采样推进与播放、暂停、拖动、倍速和设备处理速度无关；慢则排队等待，不跳过尚未分析的区间。断点恢复从最后可靠提交的采样位置继续。

解码建议用 MediaExtractor/MediaCodec 的顺序离屏适配，取需要的 PTS 并缩小分析分辨率；先用代表性媒体验证格式、时间和资源释放。不能按每个采样位置反复启动播放器或从文件头 seek。播放与分析有独立解码需求，只有资源允许才同时工作，播放保留实时预算。

两份画面预算包含仍被 OCR/渲染/API 附件引用的像素/裁图；窗口已满就停止解码，不先把整片截图存下来。需要精确单帧交互任务时按捕获的 PTS/原像素引用处理，持久恢复可重新解码；不得把压缩后的译文画面当成原输入。

### 9.2 匹配、覆盖和缓存

固定采样后再用已有区域/原文笔画匹配，减少相同画面的重复 OCR/翻译；复用结果必须满足源版本、语言/流程身份和画面证据。跨采样点的有效范围是有证据的区间；低采样率会漏掉短暂文字，界面应说明提高帧率的用途，不能声称一次 1 fps 能捕获所有短帧。

保留逐区域、逐时间范围的覆盖与人工修订；区分“已分析但无文字”和“没有分析”，否则完成率和恢复都可能错误。已完成结果供播放器即时使用；没有结果就显示原画面。跳转、换片及源版本变化先清旧遮罩，再匹配，不因后台恰好完成一段就贴到当前时刻。

正式成果包含时间、区域、译文、来源与版本；原始全帧、预处理和音频片段归可重建缓存，按视频预算和全局预算清理，当前使用者和恢复关键记录受保护。备份/成果导出不包含原视频、模型、凭据或可重建的大量中间帧。

## 10. 字幕来源、声音路线与并行

字幕分支支持外部 SRT、容器内可解析的文字字幕；声音无字幕时走专用离线 ASR，或用户明确选择的真实音频 API。图形字幕轨不能伪装成文本轨；不支持的格式说明能力并给可用来源，不能显示“没有字幕”掩盖解析失败。

现有 SRT/文字工作流可以先迁入新队列，但**不能据此把无字幕视频的“仅字幕”宣称完成**。原计划 2.4 的 whisper.cpp / sherpa-onnx 组件、模型、时间戳、体积、峰值资源、语言质量、取消/释放和 ARM 实测继续是前置评估，生产只选一套运行时。

字幕流水线：音轨/字幕源 → 分段文字及原始时间 → 稳定 cueId → 邻近上下文翻译 → 逐段保存。ASR 分段重叠要去重并恢复绝对时间；人工删除/改时不被恢复任务补回；只有文本而没有时间戳的 API 不当作已完成字幕对齐。API 音频上传是用户选定路线的明确能力，不因已有文字 API 配置就自动上传声音。

画面和字幕是同一父任务下的资源受控分支，可以相互独立完成；不重复解码不需要的画面，不因仅字幕先加载 SEG/OCR。ASR 与本地机翻/GPU 冲突时由全局调度减并发，不能各自按“最大线程数”并发撑爆内存。

## 11. 全应用唯一的任务与资源入口

### 11.1 统一什么，怎样渐进接入

新增最小 `TaskStore + TaskScheduler + ResourceGovernor + TaskExecutor`，不是重写所有业务。一个 taskId 对应一次明确工作意图，支持 parentTaskId/来源/内容引用/配置快照/优先级/恢复点。章节翻译、单页、视频画面、字幕/ASR、导出、扫描/元数据等通过执行器注册；将来 Agent 只是提交同一任务 API 的另一个发起者，不能自开线程绕过。

数据库是任务与暂停/恢复意图的唯一事实源；通知、首页进度、列表状态和任务页从同一投影生成，不再合成“看起来在任务队列里”的临时单页卡片。任务页一个入口，按类型/来源筛选，视频任务可展开画面/字幕分支；显示等待原因、资源阶段及已完成工作量。

不要为一小时视频每个采样位置预创建数千独立顶层任务；持久父任务、必要分支与检查点，按需生成小工作单元。播放会话、屏幕翻译会话、封面解码等也通过统一资源准入，但不把每个播放帧、点击和 UI 动画写成任务历史。**资源准入唯一，任务粒度按可管理的工作意图划分。**

旧章节任务与导出 payload/journal 先保留，由适配器成为唯一派工入口；禁止“新队列显示、旧 runner 仍自行派工”。迁移完成一个类型就切断它的旧准入，处理旧在途记录，再迁移下一类型。统一后的全局队列规则替代互相通知暂停的临时标记；原有明确的用户排序/资源利用策略要映射到新策略并验收。

每个类型的状态权威在切换时明确迁移到 TaskStore；旧 JSON/表中的业务快照、发布 journal 可以继续使用，重复的任务状态只能作单向兼容投影，不和新状态双向竞争。跨资源的模型下载、扫描/封面、备份恢复等现有入口也要登记适配，避免只统一翻译而遗留另一个资源派工入口。

### 11.2 优先级必须落实到资源

| 工作 | 调度规则 |
|---|---|
| 播放解码/音频输出 | 保留实时资源预算，不能等整部翻译结束才能播放 |
| 用户“翻译本页/本画面” | 新建真实交互任务，立即排到可执行队列首位；优先获得下一个空闲的必要资源，不把整个视频/漫画批次永久升级 |
| 用户主动启动的屏幕连续翻译 | 会话内有界工作单元，与其他任务同一预算；不可无限占用全部机翻/API |
| 普通章节/视频/字幕/导出 | 同级按用户排序并对等待任务做公平准入/防饿死；资源不冲突可并行 |
| 自动新增发现/缩略图等维护 | 低优先级、有界，避免抢掉播放和交互的解码/IO |

在视觉、本地机翻、API 的等待者中传递 TaskContext/优先级；只把队列项移到第一行不能算修好。“翻译本页”可见验收：点击后出现可管理、可取消、可恢复的 taskId，资源释放后先于普通等待项获得准入。

抢占发生在下一资源准入/安全工作单元边界，不强行中断已进入的 native 调用。正在发布的原子成果允许完成；进行中的整作品 API/流式请求不能因为插队或改顺序就随意重发、重复计费。独立资源能先执行则先执行；共享资源仍被占用时明确显示等待原因。高优先级不承诺“零延迟”。

### 11.3 资源预算、暂停、取消与恢复

统一管理解码、CPU/模型线程、视觉 GPU/NPU、模型内存、图像缓存、磁盘 IO、提供方 API 并发/限流。保留已有底层 session 池和 API limiter 的机制，但额度由同一资源治理入口决定。避免任务持有整页大内存和一个资源许可，却等待另一个许可造成反向堵塞；按阶段申请/释放，并规定多资源获取顺序。

持久状态至少区分：`QUEUED / WAITING / RUNNING / PAUSING / PAUSED / CANCELLING / CANCELLED / SUCCEEDED / FAILED / INTERRUPTED`；等待原因另列模型、权限、资源、网络、系统限制，父任务可有部分完成。用户暂停意图和系统中断原因分字段，不因重开应用、插队任务结束或通知恢复而擅自解除用户暂停。

- 暂停：停止新准入，处理安全边界，检查点落盘后才显示已暂停；已有完整成果保留。
- 取消：递增任务执行代次/发布令牌，等待归属资源释放；迟到结果先核对任务代次和成果 revision。原子提交已经先完成的结果保留，不能先显示取消成功却继续覆盖人工成果。
- 重复提交：对内容+目标范围+语义配置的活动任务幂等返回；新任务实例不用毫秒时间戳冒充唯一代次。失败重试、部分续跑与有意重译是不同命令。
- 全局“继续”不自动重试 FAILED 或远端结果未知的请求；显式“重试失败”单列。后台队列已被用户暂停时，用户新点“翻译本页/本画面”可仅准入这次明确操作，后台暂停意图仍保持，并给状态说明；不能在交互任务结束时顺带恢复整个队列。
- 崩溃恢复：过期执行租约对应的 RUNNING 先归 INTERRUPTED；以已提交成果和检查点对账。用户暂停的仍暂停，系统可恢复项按能力/许可条件恢复；系统强行停止应用后不能承诺自行重新启动。
- 提交一致性：先原子保存成果/发布回执，再推进检查点；重启遇到“成果已写、进度未写”不重复付费请求。远端没有幂等支持、响应丢失时记录请求结果未知，不承诺能做到远端恰好一次。

父视频的“暂停翻译”暂停它的两个工作分支；任务页可单独暂停/重试某一分支。native 长时间不返回时显示正在停止/异常等待，不能因超时就假装释放许可，再向同一仍在执行的 session 派发新调用。

清译文、换源文件、改配置、备份恢复都经过相同协调和成果写入屏障。人工成果、手工删除和样式更改沿用本次之前 1.4 已有的保护原则。

### 11.4 Android 后台宿主

一个调度体系可以有不同平台宿主，不能拿播放服务伪装所有计算。播放器用适用的媒体播放会话；用户启动的视频离线处理评估适用的 `mediaProcessing` 前台服务，网络阶段按实际类型声明；旧 Android 的能力差异单独适配，不能直接调用新类型常量当成已经支持。具体类型以平台适用范围和实机验证为准，参考 [前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)。

Android 15+ 的部分前台服务有后台累计运行时限，Android 16 的长期 WorkManager 工作也受 job quota 影响；因此不能以“包一层 WorkManager”承诺无限后台运行。到达系统限制时保存检查点并说明恢复条件，参考 [前台服务超时](https://developer.android.com/develop/background-work/services/fgs/timeout)和[长期 Worker 限制](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)。

通知暂停/继续、应用内操作和系统停止回调都落到统一任务命令。后台服务拒绝启动、超时、省电/内存回收必须有可恢复状态，通知消失不能留下无归属任务和已加载模型。

## 12. 数据、迁移、分享与导出

建议数据分层如下，具体表名实施时遵从现有规范，不借此重写漫画数据库：

| 层 | 主要内容与原则 |
|---|---|
| 系统媒体索引 | 每卷/MediaStore ID/完整母目录、元数据、水位与可访问状态；行 ID 是定位，不是内容哈希 |
| 视频正式身份 | 稳定 videoId、当前 locator、源内容 revision/必要时完整摘要、播放进度与统计；移动/重索引先核对后重绑定 |
| 书架关系/偏好 | videoId 与分类引用；全局图片/视频选择、各页独立筛选和滚动状态 |
| 任务 | UUID 实例、父子关系、配置/范围、状态/暂停意图/执行代次/检查点和请求记录 |
| 正式成果 | 帧与区域时间索引、气泡轨/几何/人工修订，字幕源/译文/时间/删除保护和 revision；原成果文件可继续引用 |
| 缓存 | 缩略图、解码帧、预处理、音频中间片段；有所有者、预算和活动租约，不冒充正式成果 |

目录改名或权限失效不立即换 videoId；内容真的替换时旧成果保留为旧源版本，不能因文件名/大小相同就重新绑定。浏览全库不哈希，实际开始翻译/恢复既有成果时做必要内容校验；大文件检查也要有取消、进度和资源预算。

旧 `files/videos` JSON 逐个验证、迁移、记录完成标记，成功前保留原副本；旧 SAF URI、源摘要、观看位置、字幕 ID、成果 revision 和人工标记全部继承。原先手动导入的视频加入迁移后的书架，保持可找到。系统发现同一媒体通过 locator/受控内容校验合并，不能因扫描创建重复成果项目。旧帧信息不足以推断区域跨帧轨道时保留为独立旧区间，不能虚构连贯时间。

备份同时覆盖新视频表、书架关系、任务可恢复元数据、偏好与成果；MediaStore ID 在其他设备不保证有效，恢复先标待定位/授权。恢复旧备份不删除本机新视频数据；在途任务和恢复过程协调，不能边恢复边写原成果。原视频、模型和缓存不跟随成果备份。

分享原视频采用系统分享 URI 权限；成果包和字幕导出捕获点击时的成果 revision 与样式，由统一导出任务生成，失败不暴露半文件。先支持 SRT 和带 manifest/版本/源摘要/画面区域及字幕的可恢复包。**“导出带译文的新 MP4”会涉及重新编码，原计划明确排除，建议继续作为单独范围，不用成果包冒充视频导出。** 菜单直接写明导出类型。SRT 本身不保存字体/颜色，样式写成果包；不能声称 SRT 导出包含智能颜色效果。

## 13. 分批执行与完成标准

不按文件数或写了多少测试评估完成，按用户路径交付。每批记录完成、未验证和下一项；内部里程碑不叫“视频整体完成”。ASR 小样本评估可以从前期并行做调查，不把整个播放器拖到 ASR 之后。

| 批次 | 任务 | 可以独立验收的产物 | 依赖 |
|---|---|---|---|
| R0 契约与基线 | 固定列表/播放器/两种编辑状态、采样/任务状态/迁移契约；复现单页优先级；登记现有数据样本 | 本文细化的状态与兼容清单、最少代表性媒体，不扩成通用平台 | 先做，范围短 |
| R1 队列与单页优先级 | TaskStore/准入/执行代次，章节/单页/导出/屏幕与维护执行器接统一资源；修复翻译本页真实入队 | 单页立即可见、下个资源先执行、暂停/取消/重启可靠；现有业务仍可用 | R0，后台视频前置 |
| R2 图库/书架视频 | MediaStore 首扫/增量/刷新、权限、分页封面、母目录筛选、六类排序、共用模式记忆、视频书架与旧数据迁移 | 无需导入就能看到/收藏，横竖切换与重启记忆正确；图片路径无退化 | R0；资源任务接 R1 |
| R3 播放器 | Media3、透明控制栏、完整手势/锁定/速度/音轨/循环/列表/PiP与位置恢复 | 点击直达播放，所有控制可用，当前成果按时间正确显示 | R2，资源接 R1 |
| R4 后台画面+已有字幕 | 固定 PTS 采样、两个在途画面、有界缓存、画面/文本执行器、选项/自动入书架/联合进度 | 不开播放器也能推进，退出可续，单帧可插队，已有 SRT 与画面分支可并行且单独恢复 | R1–R3 |
| R5 编辑与成果交付 | 共用气泡编辑、区域时间带、独立字幕工具、增删改时/跳段、样式/智能颜色、清理和成果/SRT导出 | 人工成果可保存/撤销/恢复，迟到机器不覆盖，跨应用分享与导出可读取 | R3–R4；基础数据按 R0 预留 |
| R6 声音与最终收口 | 完成前期 ASR 实测并集成一套，实际音频 API 可选；三种模式全链路、后台限制、长视频与 Release 回归 | 无字幕视频也有明确可用的字幕路线；所有当前工作走同一准入，无残留旁路 | 原计划 2.4/4.1，及 R1–R5 |

R1 避免先把所有 payload 搬库：先建共同记录/资源准入，适配现有执行器并关闭旧派工入口。R2/R3 提供可见的产品进展；R4 之前不再把“播放器里能点翻译”当作后台翻译交付。每批保持可构建和数据可读取，必要时用受控切换开关，不能同时运行两套写入者。

原计划 1.5 的能力补齐继续与 2.1 设置折叠随 R1/R4 收口；1.3 余项仍按原登记处理。阅读器本页分享/保存、GitHub 用户统计、管道和只读目录继续作为独立待办，不因本次视频重做被默默删除，也不拉来充当本次视频完成条件。

Codex 负责架构、复杂时序、冲突判断和最终验收；本地 DS 承担有明确文件范围的实现/只读调查、确定性测试、一次增量打包和明确授权的设备执行。DS 报告要核对原始证据。发布/手机交付使用既有 Release 签名和包名，保留数据，不能再把 Debug 副本当作原应用覆盖交付。

## 15. 需在首批冻结的建议默认，不阻塞本轮方案交付

1. 中间双击暂停、两侧双击 ±10 秒；长按 2 倍松开复原，水平整幅约 20% 总时长。

5. 导出先交付字幕与可恢复成果包；带译文 MP4 保持原计划的独立范围。
