# v0.1.7

## 中文

- 修复取消翻译队列全部任务后重新添加 API 任务一直等待、资源数为 0 的问题。取消从引擎预热阶段就开始生效，替代任务等待旧工作线程真正结束清理；空闲资源释放只等待对应的旧调度器，不阻塞新调度器。
- 引擎协调以实际驻留实例及其后端配置为依据，不以相邻任务之间的差异代替当前状态。保留仍需要的兼容模型，只预热当前任务所需资源，不提前加载后续任务的 OCR 或本地翻译模型。
- 正在使用的引擎实例不卸载、不阻塞配置协调；视觉实例在空闲后清理不再需要的资源，后端变更在下一次使用时替换。屏幕翻译的独立视觉池和共享本地翻译模型的会话占用保护保持有效。
- 章节正常完成后，继续执行工作流中的后续步骤，不把已完成章节误判为取消。原有单页失败跳过、失效章节不影响后续章节的行为保留。

沿用原发布证书，支持保留数据的覆盖升级。Android 8.0+，arm64-v8a / x86_64；版本代码为 9。

## English

- Fix API jobs remaining pending with no loaded resources after cancelling all queue jobs and adding a replacement. Cancellation now covers engine preparation; replacement workers wait for old workers to finish cleanup, and idle resource release waits for the captured old scheduler instead of a newly started one.
- Reconcile resident engine instances and their actual backend settings rather than differences between adjacent jobs. Retain compatible models still needed, warming only current requirements instead of eagerly loading future OCR or local translation models.
- Never unload occupied engine instances or wait on them while coordinating configuration. Vision workers trim obsolete resources when idle and replace incompatible backends on their next use. Screen translation keeps its independent vision pool and pinned shared local translation models.
- Allow post-publication workflow steps to finish after chapter rows become completed. Existing failed-page isolation and continuation past unavailable chapters are preserved.

Uses the existing release certificate for in-place upgrades preserving app data. Android 8.0+, arm64-v8a / x86_64; version code 9.

## 验证与边界 / Verification And Limits

- 功能修复在 2026-10-12 已完成定向 Android 回归：覆盖取消后立即入队、资源卸载后重新入队、引擎加载期间取消、只预热当前资源、工作流收尾、屏幕引擎热切换与视觉实例占用保护。最新边界回归 5 项与引擎池 4 项全部通过；屏幕快速配置修改恢复用例也已通过。
- Targeted Android regressions on 2026-10-12 covered immediate restart after cancellation, restart after model release, cancellation during preparation, current-only warm-up, workflow tail steps, screen engine hot reload and occupied vision instances. The final five boundary checks and four pool checks passed; rapid screen configuration recovery also passed.
- 同一功能代码的签名 Release 已在实体手机完成保留数据的覆盖安装并核对 APK 哈希。此次版本递增后的 APK 将重新构建和签名，发布附件中的 `release-metadata.json` 与 `SHA256SUMS` 记录其独立版本、源提交和校验信息；不将旧 APK 的安装验证当作新 APK 的实体机验证。
- The same functional code in a signed Release passed an in-place phone upgrade and installed-APK hash verification. This version increment rebuilds and signs a distinct APK; attached `release-metadata.json` and `SHA256SUMS` record its version, source commit and checksums. Prior APK installation evidence is not a device test of the newly versioned APK.
- 项目许可证选择、SEG 权重分发依据、完整依赖审查及真实云提供方与 ARM 长时后台验证仍沿用已有待办，详见 [v0.1.6 发行说明](v0.1.6.md)。
